# AAR: Pipeline Ad-Hoc Patterns — Elevation to Idiomatic Rust

**Date**: 2026-06-12  
**From**: eastGate overwatch  
**Wave**: 111  
**Status**: DIAGNOSIS — patterns identified, elevation paths documented

---

## Context

Teams are performing repeatable work outside of idiomatic Rust automation:
manual freshness commits, doc pushes, handoff writes, FRAGO edits, and conflict
resolution. Each of these is a signal that `cellMembrane` hasn't yet absorbed
the pattern into its automated pipeline.

**Principle**: If a team does it more than twice, it should be a `membrane` command.
If it creates merge conflicts, it must be atomic. If it requires coordination,
it must be orchestrated.

---

## Identified Ad-Hoc Patterns

### 1. Manual Freshness Commits (HIGHEST FREQUENCY)

**Current behavior**: After a primal team pushes a commit, someone (often the same
team, sometimes overwatch) manually edits `freshness.toml` → commits with message
like "freshness: songBird fe47c012" → pushes to both remotes.

**Evidence**: 20+ commits in wateringHole history with pattern `freshness: <primal> <sha>`.

**Root cause**: `publish_freshness_toml()` in `cellMembrane` writes the file during
cascade, but does NOT commit or push it. Teams fill the gap manually.

**Elevation path**:
```
membrane temporal.cascade --publish-freshness
```
Should atomically: write freshness.toml → `git add freshness.toml` → `git commit -m
"freshness: auto-publish (cascade {gate}@{timestamp})"` → push to sovereign remote.

**Conflict mitigation**: If multiple gates cascade in the same window, the second
push fails (ff-only). Solution: re-read remote HEAD, re-generate freshness, force-push
(safe because freshness.toml is machine-generated, not human-authored). Or: use a
dedicated `freshness` branch that gates merge-commit into.

**Idiomatic Rust**: Extend `post_sync.rs` to include git-add + commit + push after
`publish_freshness_toml()` succeeds. Add conflict detection + retry.

---

### 2. Per-Primal Freshness Updates (REDUNDANT)

**Current behavior**: When a single primal pushes a new commit, a team immediately
updates just that one entry in `freshness.toml` and commits.

**Why this is wrong**: Freshness should reflect *cascade state*, not individual pushes.
A primal can push 5 commits between cascades — we only care about the state *after*
the next cascade pulls them all.

**Elevation path**: Remove per-primal freshness updates entirely. `freshness.toml`
is ONLY regenerated by `membrane temporal.cascade --publish-freshness`. If teams
want to track individual primal HEADs between cascades, use `membrane health.audit
--mesh` (which already compares provenance against live HEADs).

**Idiomatic Rust**: Already implemented (`health.audit --mesh` in `e80993f`). Just
stop doing manual per-primal freshness edits.

---

### 3. Doc Writes + Push (COMMON)

**Current behavior**: Overwatch writes handoffs, AARs, blurbs, FRAGOs manually →
stages → commits → pushes to both remotes. This is the pattern we're doing *right now*.

**Observation**: This is creative work (content authoring) that can't be fully
automated. However, the *mechanics* (stage, commit, push to both remotes) should be
a single command.

**Elevation path**:
```
membrane docs.publish --message "wave111: AAR divergence results"
```
Should: `git add handoffs/ impulses/` → commit with standard message → push to
sovereign + mirror remotes. Optionally auto-add `Co-authored-by` trailer.

**Idiomatic Rust**: New dispatch command in `membrane-shadow/src/dispatch/docs.rs`.
Low complexity — it's just the push mechanics that should be a single invocation.

### 4. Freshness Conflict Resolution (HISTORICAL)

**Current behavior**: When two gates cascade simultaneously, `freshness.toml` diverges.
Resolution: `git checkout --theirs freshness.toml && git add freshness.toml && git commit --no-edit`
(documented in `DEPLOYMENT_INSTANCE.toml` line 250).

**Why this persists**: Machine-generated files get merge conflicts because git treats
them as regular source.

**Elevation path**: Two options:
- **Option A (simple)**: Freshness auto-publish uses `--force-with-lease` since the
  file is machine-generated and latest-wins is always correct.
- **Option B (correct)**: Move freshness tracking to songBird mesh gossip (the
  DEFERRED item `freshness_mesh` in Stream 5). Each gate announces its local HEADs
  via mesh. No central file to conflict on.

**Idiomatic Rust**: Option A is immediate (add to post_sync.rs). Option B is the
endgame but requires songBird mesh publish wiring.

### 5. FRAGO Status Updates (MODERATE FREQUENCY)

**Current behavior**: After a team ships something, overwatch manually edits the
FRAGO TOML to mark items as DONE with commit references.

**Observation**: This is partially a judgment call (what counts as "done") but
the mechanical part (reading commit history, matching against FRAGO item IDs,
updating status field) could be semi-automated.

**Elevation path**:
```
membrane impulse.resolve --item CASCADE-STALE-RECOVERY --commit acab3f6
```
Should: parse the FRAGO TOML → find the item → set `status = "✅ DONE ({commit})"` →
commit the change.

**Idiomatic Rust**: New command in `dispatch/docs.rs` or `impulse/` module. TOML
parsing already exists throughout the codebase.

---

### 6. Depot Rebuild Trigger (OPERATIONAL)

**Current behavior**: After primals push new code, someone has to remember to run
`membrane plasmid.harvest --targets <primal>` on the VPS. Currently this is a
manual SSH + command invocation.

**Why it matters**: The depot (plasmidBin) goes stale between harvests. songBird
depot is currently at `32a8d700` but HEAD is `fe47c012` — 2 commits behind.

**Elevation path**: Two stages:
- **Stage 1 (cascade hook)**: `temporal.cascade` on VPS detects freshness drift
  against provenance.toml and auto-triggers `plasmid.harvest` for stale binaries.
  (Already partially wired — `ENV_AUTO_REBUILD` flag exists in `post_sync.rs`.)
- **Stage 2 (event-driven)**: songBird mesh announces new commits; VPS listens and
  auto-rebuilds affected binaries on push.

**Idiomatic Rust**: Stage 1 is mostly done — just needs `MEMBRANE_AUTO_REBUILD=1`
to be set in the VPS environment. Stage 2 requires songBird mesh event wiring.

---

### 7. Remote Parity Push (FREQUENT)

**Current behavior**: After committing locally, teams must `git push origin main &&
git push forgejo main` — two separate commands. If one fails, parity breaks.

**Elevation path**: Already solved by `temporal/resolve.rs` — the cascade push logic
handles both remotes with authority-first ordering. But teams making *manual* commits
(docs, FRAGOs) still do double-push manually.

**Elevation**: `membrane docs.publish` (pattern 3) should handle dual-push. For all
other cases, the standard commit flow should be:
```
membrane git.publish --message "description"
```
Which stages, commits, and pushes to all configured remotes with authority ordering.

**Idiomatic Rust**: Thin wrapper around existing `resolve.rs` push logic.

---

### 8. Handoff Archival (PERIODIC)

**Current behavior**: At wave transitions, overwatch manually moves handoffs from
`handoffs/` to `handoffs/archive/wave{N}/`. This involves `mkdir -p`, `git mv`,
commit, push.

**Elevation path**:
```
membrane wave.close --wave 111
```
Should: identify completed handoffs → move to archive → update FRAGO status →
commit with standard message → push.

**Idiomatic Rust**: New wave lifecycle command. Pattern recognition for "completed"
handoffs (AAR prefix, resolved FRAGO items) can be heuristic initially.

### P1: Freshness Auto-Publish Complete (extend post_sync.rs)

5. On push conflict: re-fetch, re-generate, retry once

New dispatch command:
- Stages `handoffs/` + `impulses/` changes in wateringHole
- Commits with provided message + auto-trailer
- Pushes to both remotes with authority ordering
- Reports success/failure per remote

### P3: `membrane impulse.resolve` command

- Parses FRAGO TOML by item ID
- Updates status field with `✅ DONE ({commit})` template
- Commits atomically

## Endgame: Freshness via Mesh Gossip

The deferred Stream 5 item (`freshness_mesh`) is the correct long-term solution:
- Each gate's songBird announces its local HEAD SHAs via `mesh.publish`
- Any gate can query the mesh for ecosystem-wide freshness without a central file
- No `freshness.toml` conflicts — the file becomes a snapshot/cache, not SSOT
- `health.audit --mesh` already does this comparison — just needs live data feed

This eliminates Pattern 1, 2, and 4 entirely. But it requires songBird mesh event
infrastructure that isn't wired yet.

**At that point, the only manual work in the pipeline is creative content authoring.
